# Деплой, бэкапы, безопасность

## Целевая среда

- **VPS в РФ или на нейтральном хостинге** — доступ из РФ без VPN,
  независимость от сервисов Google/Amazon.
- Ничего из заблокированных/недоступных внешних сервисов не используется:
  нет email-отправки, нет облачных API, нет CDN.

## Стек деплоя

- Node-приложение (Nuxt 4 + Nitro) под **systemd** (автостарт, рестарт).
- **Caddy или nginx** как reverse-proxy с TLS (Let's Encrypt).
- Порт приложения слушает только localhost; наружу — только proxy.

## Бэкапы

1. **Контент** (`content/`): git-push на второй сервер / bare-репозиторий /
   внешний носитель. Регулярность — по расписанию (Nitro Task или системный
   cron на сервере).
2. **Пользователи** (`users/`) и **сессии** (`sessions/`): rsync-копия
   (секреты в git не попадают).
3. Восстановление на новом сервере: `git clone` контента + rsync `users/`.

## Приватность и защита данных

- **Персональных данных нет по дизайну**: нет email/телефона/имён,
  аккаунт = псевдоним + пароль. Соответствие «человек ↔ псевдоним» — вне системы.
- **Без аналитики и трекеров.**
- **Логи доступа без IP** (nginx/Caddy: отключить или маскировать $remote_addr).
- Куки только сессионные, `httpOnly`, `SameSite`.

## Безопасность приложения

- Пароли: argon2. Rate-limit на попытки входа.
- Markdown: рендер + **server-side sanitization** (защита от XSS).
- Файлы-вложения: whitelist расширений и лимит размера; хранение **вне
  webroot**, выдача через контролируемые роуты с проверкой прав на каждый файл
  (работы учеников скрыты друг от друга — авторизация обязательна).
- Права ролей: `admin` > `teacher` (свои курсы) > `student` (свои сдачи,
  чтение материалов своих курсов). Проверки прав — на уровне роутов + портов.
- CSRF-защита форм/мутаций.

## Dev-практика (по правилам окружения)

- После правок: `npx vue-tsc --noEmit` (типы), `npx eslint <пути>`, точечно.
- Тесты слоя хранилища (vitest): файловый адаптер, статусы сдачи, права.
- Сборка `npm run build` как финальная проверка; dev-сервер — только по явной просьбе.
