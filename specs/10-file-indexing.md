# Файловая индексация: id/slug, индексы, write-очередь

Зафиксированный дизайн хранения сущностей (темы/материалы, задания, позже —
комментарии). Цель: сделать файловую структуру безболезненной для
переименований и связей, не уходя от файлов и git как источника истины.

## Проблема

`slug` сейчас одновременно: имя директории, ключ в API/URL и цель
`[[вики-ссылок]]`. Переименование требует `rename()` каталога + переписи
ссылок + чревато коллизиями и «замороженными» URL.

## Принципы

1. **Сущность — источник истины.** `*.yml`/`*.md` содержат всё, включая
   `id` и `slug`. Индексы — производные, всегда пересобираемые сканом.
2. **Slug — проекция.** Снаружи (API, URL, `[[ссылки]]`, UI) оперируем
   slug'ами; внутри — иммутабельным `id`. Перевод — только в адаптере.
3. **Индекс — ускоритель, не авторитет.** Lookup: индекс → id → entity.
   Промах/битый индекс → fallback на скан + пересборка.
4. **Write-очередь.** Все мутации контента курса сериализуются
   per-course async-мьютексом (Node single process — promise-chain lock).
   Entity-файл и индекс пишутся в одной критической секции.
   Ограничение: работает внутри одного инстанса Node; при будущем
   serverless-деплое с несколькими инстансами потребуется пересмотр
   (CAS-ретраи / внешний лок / sticky-роутинг).

## Структура

```
content/courses/<courseId>/
  course.yml                  # источник истины курса
  _index.yml                  # указатель: slug → id по типам сущностей
  roster.yml
  materials/<id>/
    material.yml              # { id, slug, title, type, ... }
    content/...
  assignments/<id>/
    assignment.yml            # { id, slug, title, type, audience, status, due, maxPoints }
    description.md
    submissions/<username>/
      submission.yml          # { status, grade, feedback, submittedAt, updatedAt }
      answer.md
      comments/<cid>.yml      # личная переписка (см. ниже)
    comments/<cid>.yml        # общий тред по заданию
```

Имя директории = `id`, никогда не переименовывается. Допустимо, что
dir-name исторически ≠ id (миграция без move) — адаптер читает id из yml.

## _index.yml (на курс)

```yaml
materials:
  pervyy-zakon: m_a1b2c3
assignments:
  domashka-1: a_x7k2p9
```

- Один файл на курс: минимум contention, blast radius ограничен курсом.
- Lookup slug→id за O(1) — без сканов на каждый запрос.
- Каждая мутация entity обновляет индекс в той же критической секции.
- Пересборка: скан `*/<type>.yml` → запись `_index.yml`.

## Связи

**Ученик ↔ задание ↔ ответ** — индекс не нужен, структура каталогов
является индексом:

- `assignments/<id>/submissions/<username>/` — список поддиректорий =
  «кто сдал».
- `submission.yml` — статус/оценка/таймстемпы; `answer.md` — ответ.

**«Мои работы по всем курсам»** — пока скан всех курсов (их единицы).
Позже, при появлении страницы, добавить per-user индекс:

```
users/<username>/_index.yml
  submissions:
    - course: inf, assignment: a_x7k2, status: returned, grade: 5
```

(размещение — рядом с `users/<username>.yml`, вне `content/`.)

## Переписка по заданию (следующий шаг)

Два вида тредов, оба — файлы:

- общий тред: `assignments/<id>/comments/<cid>.yml`
- личный тред: `assignments/<id>/submissions/<username>/comments/<cid>.yml`

```yaml
# comments/<cid>.yml
id: c_01J...          # ULID/timestamp-префикс → сортировка по имени
course: inf           # контекст для будущего per-user индекса
assignment: a_x7k2
author: teacher1      # username, как везде (псевдонимность сохраняется)
scope: all            # или username для личного треда
replyTo: c_01J...     # опционально
createdAt: 2025-...
```

Текст — соседний `comment.md` в той же директории (паттерн answer.md).
Читаются по возрастанию cid.

## Операции над сущностью

- **Создание**: генерим `id` + `slug` (slugify(title), суффиксы при
  коллизии) → пишем entity → добавляем в `_index.yml`.
- **Переименование**: меняем `title`/`slug` в entity-yml + запись в
  `_index.yml` + переписываем `[[old-slug]]` → `[[new-slug]]` в контенте
  курса. Без `rename()`, без сканов на запросах.
- **Удаление**: `rm -r <id>/` + удаление записи из `_index.yml`.

## Миграция существующих данных

Разовый скрипт: существующим `materials/<slug>` и `assignments/<slug>`
проставить `id`/`slug` в yml, собрать `_index.yml`. Директории можно
не переименовывать — id читается из yml, а не из имени папки.

## Что не решает (сознательно)

- `[[ссылки]]` — текст в markdown, переписываются при переименовании
  (механика уже есть для тем).
- Гонки между инстансами (см. write-очередь выше).
- Транзакционность «entity + index» — не атомарна на уровне FS;
  рассинхрон лечится пересборкой индекса.
