# Границы MVP и дорожная карта

## MVP-скоуп (порядок сборки)

Пользователи подтвердили приоритет: **сначала полный цикл ДЗ**, контент и роли — следом.

1. **Каркас + аутентификация**
   - Проект Nuxt 4, роли `admin | teacher | student`.
   - Вход по псевдониму + пароль (argon2), файловые сессии.
   - Админ создаёт учителей и учеников; генератор человекочитаемых паролей
     (например `lisa-luna-42`) в UI.
   - Rate-limit на вход, сессионная кука `httpOnly`, CSRF-защита.

2. **Курсы**
   - CRUD курса, зачисление учеников (roster), шкала оценивания (настраиваемая
     на курс: 5-балльная / 100 / зачёт-незачёт).

3. **Материалы (плагин `doc`)**
   - Редактор markdown: textarea + live-предпросмотр (без тяжёлого WYSIWYG).
   - Рендер с sanitization, вложения, оглавление, `[[internal-links]]`.

4. **ДЗ: выдача**
   - Задание: md-описание, дедлайн, статус `draft → published`.

5. **ДЗ: сдача**
   - Ученик пишет ответ в md + файлы, статус `submitted`.

6. **ДЗ: проверка**
   - Учитель видит работу, ставит оценку + текстовый комментарий, возвращает.
   - Ученик видит feedback, может пересдать (`resubmitted`).
   - **Упрощённо**: без построчных комментариев (без анкеров к фрагментам).

## Осознанно НЕ входит в MVP

- Календарь/расписание занятий.
- Уведомления (push/email).
- Построчные (анкерные) комментарии к фрагментам.
- Графики успеваемости, статистика.
- Мульти-учитель на один курс (в MVP курс = один учитель; платформа
  мульти-учительская — у каждого свой курс(ы)).
- API-ключи, интеграции.
- Quiz/survey-плагины (архитектура готова, реализация — после MVP).

## Дорожная карта после MVP (приблизительно, по востребованности)

1. История изменений материалов (чтение git-журнала: diff по датам).
2. Второй плагин (`quiz`) — проверка контракта на несовпадении формы.
3. **Расписания (согласованный приоритет, см. `07-schedule.md`):**
   недельное расписание курса + месячный календарь учителя/ученика
   с дедлайнами ДЗ и исключениями (отмена/перенос).
4. Уведомления внутри платформы (колокольчик, без email).
5. Мульти-учитель на курс, статистика успеваемости.
6. Анкерные комментарии к фрагментам работ.
7. SQLite-адаптер хранилища — только при реальной боли от файлов.

## Критерии готовности MVP

- Учитель может: создать курс, зачислить учеников, опубликовать конспект
  и задание, увидеть сдачи, поставить оценку с комментарием, вернуть работу.
- Ученик может: войти, прочитать материал, сдать ДЗ (текст + файлы),
  увидеть оценку/комментарий, пересдать.
- Все мутации контента видны в git-журнале (commit на псевдоним автора).
- Ни в файлах, ни в логах, ни в БД нет персональных данных.
