# Git-журнал (интеграция git в файловое хранилище)

## Роли git

Git — **не** источник истины. Источник истины — файлы на диске в `content/`.
Git выполняет три роли:

### 1. Журнал истории (аудит + undo)

Каждый мутирующий запрос сначала изменяет файлы напрямую (первична запись в
файл), затем — через debounce-окно — выполняется автокоммит:

```
мутация (сдача ДЗ / правка конспекта / оценка)
  → файлы записаны атомарно                    (истина: файл)
  → debounce-окно (5–30 с, настраивается)
  → git add -A && git commit -m "<pseudonym>: <действие> (<путь>)"
```

- Все изменения в окне схлопываются в один коммит.
- Критичные действия (сдача, оценка) могут коммититься немедленно — настройка.
- Сообщения коммитов дают бесплатный аудит-лог:
  `git log --follow submissions/ivanov/` — вся история работы.

### 2. Страховка целостности

Проверку в момент записи выполняет атомарная запись и валидация YAML.
Git даёт восстановление: `git diff`, `git checkout <commit> -- путь`.
Если репозиторий удалить — система продолжит работать, потеряется только история.

### 3. Транспорт бэкапов

`content/` — обычный git-репозиторий: бэкап = `git push` на remote.
Восстановление на новом сервере = `git clone` + rsync каталога `users/`.

## Иерархия

```
диск (content/, users/, sessions/)   ← истина, всё работает через это
  ↑
git-репозиторий в content/           ← журнал + транспорт бэкапа
  ↑
git push → remote                    ← офсайт-бэкап
```

Система **не читает git как данные**: все роуты работают с файлами с диска.
Единственное чтение git — будущая фича «история изменений» (пост-MVP).

## Механика

- Коммиты выполняет **один воркер** (очередь): конфликтов слияния не бывает,
  т.к. репозиторий локальный и однонаправленный (никто не пушит в него извне).
- Автор в сообщении коммита берётся из контекста запроса (псевдоним), а не из
  git-конфига. Коммитер — системный пользователь `system`.
- Ручные правки учителем по SSH попадут в историю как коммиты `system` —
  честно и безопасно.
- Между записью файла и коммитом есть окно debounce: при падении процесса файлы
  целы (они уже на диске), «недожурнал» допустим.

## Что НЕ в git

- `users/` (хэши паролей) и `sessions/` — секреты, бэкапятся rsync-копией.
- В коммитах фигурируют только псевдонимы — пуш на сторонний remote безопасен
  в духе принципа «минимум персональных данных».
