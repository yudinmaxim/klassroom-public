# QR-вход

> **Статус: реализовано.** `qr-tokens/`, `POST /api/users/[username]/qr`
> (пермишен `users.qr.generate`; учитель — только участникам своих курсов),
> `POST /api/auth/qr` (410 при сгоревшем/просроченном токене), страница
> `/login/qr?t=…`, кнопка «QR-вход» на `/admin/users` с клиентским рендером
> QR (пакет `qrcode`, без внешних сервисов). TTL «класс» 15 мин / «дом» 7 дней;
> регенерация гасит прежний токен. Зависимость в UI от правки копирования
> ссылки через метод (navigator недоступен в шаблонах Vue).

Согласованный приоритет: после ролей/пермишенов (спека 08), до/вместе с
расписанием (спека 07) — точный порядок определит востребованность.

## Задача

Вход без ввода пароля: учитель/админ генерирует QR-код для конкретного
ученика, ученик сканирует его своим устройством и сразу попадает в свой
аккаунт. Полезно: младшие классы, «раздать входы в кабинете», снижение
барьера первого входа.

## Модель токенов

- Токен — случайные 128 бит (hex), НЕ содержат ни имени, ни псевдонима.
- Хранение: `qr-tokens/<token>.yml` (рядом с `users/`, в git не попадает):

```yaml
username: ezhik-7
createdAt: 2026-11-12T00:00:00Z
expiresAt: 2026-11-19T00:00:00Z
```

- Одноразовый: использование (успешный вход) сжигает токен.
- TTL настраиваемый: два режима — «раздать в классе» (~15 минут) и
  «на дом» (~7 дней). Регенерация для того же ученика гасит старый токен.
- Файлы токенов удаляются после сжигания/истечения (сборкаNitro-таской).

## Поток

1. Владелец `users.qr.generate` открывает в разделе пользователя
   «QR-вход», выбирает TTL, получает QR-картинку (клиентский рендер,
   библиотека `qrcode` — без внешних сервисов).
2. Ученик сканирует → открывает `GET /login/qr?t=<token>` → страница
   вызывает `POST /api/auth/qr {token}` → сервер проверяет и сжигает токен,
   создаёт обычную сессию → редирект на главную.
3. Всё, что видит ученик дальше, определяется его ролью (спека 08).

## Права и защита

| Аспект | Решение |
|---|---|
| Кому можно генерировать | Пермишен `users.qr.generate`; учитель — только для учеников, состоящих в его курсах (проверка rosters его курсов), админ — для любых |
| Приватность | Токен обезличен; в QR и логах нет имён |
| Перебор | 128-бит токен + rate-limit на `/api/auth/qr` (общий с login-лимитом) |
| Компрометация | Токен = вход без пароля; TTL короткий, одноразовость, регенерация гасит старый |
| Отзыв | «Сбросить» = удалить текущий токен пользователя |

## UI

- Раздел пользователя (admin/users, позже — страница курса): кнопка
  «QR-вход» → модалка с QR + печать (лист А4 с инструкцией для ученика).
- Страница `/login/qr` — авто-проверка токена, состояния: «вход выполнен»,
  «ссылка устарела», «ссылка уже использована».

## Вне скоупа

- QR «на весь класс» (один токен → выбор своей учётки из списка) — отдельная
  задача, если понадобится; сейчас токен всегда привязан к одному аккаунту.
- Напоминания/уведомления через QR — нет.
